# 第9章 Q6_K：6-bit 子块与输出层

在 k-quant 家族里，Q6_K 是一个"看起来低调、实际上特殊"的成员。它不像 Q4_K 那样有显眼的市场地位，也没有 Q5_K 那样清晰的角色描述，可它偏偏做了一件其他 k-quant 都没做过的事：**改变子块结构**。

回顾第 7 章，Q4_K 的骨架是"256 值超级块 = 8 个子块 × 32 值，每个子块有 6-bit 尺度 + 6-bit 最小值"。Q5_K 基本保留了这个骨架，只是额外加了一层高位平面。而 Q6_K 干脆把骨架换成了 **16 个子块 × 16 值**：每个子块用一个 8-bit 有符号整数做尺度，并且**完全去掉了最小值偏移**。结构反而更简单了，精度却更高——它的有效位宽是 6.5625 bpw，在 k-quant 家族里是仅次于 Q8_K 的高精度档位。

不过，它更重要的身份其实体现在**角色**上：在 `Q4_K_M`、`Q5_K_M` 这些文件里，输出嵌入层（`output.weight`）几乎总是用 Q6_K。为什么偏偏选它？因为输出层直接决定了最终 logits 的分布，而这里是全模型对量化误差最敏感的地方之一。这一章就会把这层因果关系解释清楚。

还是先把几个术语统一一下。**子块（sub-block）**：超级块内部更小的单元，Q6_K 里是 16 值。**子组（sub-group）**：本书按照细纲的写法，用这个词来指代 Q6_K 的 16 值子块。**logits**：模型最后一层输出的原始分数，经过 softmax 之后变成 token 概率，PPL 和生成质量都是从这里来的。**输出嵌入层（output embedding / output.weight）**：把最终特征映射成词表概率的那一层。**对称量化（symmetric）**：反量化公式里只有尺度、没有偏移项（也就是最小值），量化范围关于 0 对称。


## 9.1 结构：16 个 16 值子块

### 9.1.1 `ql[128]` 低 4 bit + `qh[64]` 高 2 bit

先看结构体：

```c
typedef struct {
    uint8_t   ql[QK_K/2];      // 低 4 位平面，128 字节
    uint8_t   qh[QK_K/4];      // 高 2 位平面，64 字节
    int8_t    scales[QK_K/16]; // 16 个子块的 8-bit 有符号尺度
    ggml_half d;               // 超级块尺度，2 字节
} block_q6_K;
static_assert(sizeof(block_q6_K) == sizeof(ggml_half) + QK_K/16 + 3*QK_K/4,
              "wrong q6_K block size/padding");
```

这里的字段顺序和 Q4_K 不一样：`ql`、`qh`、`scales` 排在前面，`d` 排在最后。每个权重占 6 bit，被拆成 **低 4 位 + 高 2 位** 两个平面：

```
一个权重 6-bit 码的平面拆分

  码 = 6 bit（0..63）
  ┌────────┬────────┐
  │ 高 2 bit │ 低 4 bit │
  └────────┴────────┘
       │          │
       ▼          ▼
  集中在 qh[64]  分散在 ql[128]
  1 字节装 4 个   1 字节装 2 个
  权重的高 2 位   权重的低 4 位
```

先来算字节总量：

\[
128 \text{（ql）} + 64 \text{（qh）} + 16 \text{（scales）} + 2 \text{（d）} = 210 \ \text{字节}
\]

再看有效位宽：

\[
\text{bpw} = \frac{210 \times 8}{256} = 6.5625 \ \text{bit/weight}
\]

拿它和 Q5_K 的 5.5 对比一下：多出来的 1.0625 bit 里，有 1 bit 是因为"高位平面从 1 位变成 2 位"，剩下的 0.0625 bit，则来自子块尺度从 6-bit 升级到 8-bit 之后分摊到每个权重上的那一点点。

### 9.1.2 8-bit 有符号子块尺度 `scales[16]`

Q6_K 的每个子块（16 值）都有属于自己的尺度，不过和 Q4_K 相比，有两点关键的不同：

1. **类型是 `int8_t`（8-bit 有符号）**，取值范围是 -128..127，比 Q4_K 的 6-bit 无符号（0..63）精度高一倍以上；
2. **没有 `dmin`，也没有最小值偏移**。`block_q6_K` 里压根就没有 `dmin` 这个字段——它是**对称量化**：只用一个尺度，就把值映射到关于 0 对称的码范围，不需要任何偏移项。

这带来一个很直观的好处：**结构更简单**。Q4_K 得处理"尺度+最小值"两组 6-bit 参数那种复杂的交错打包（第 7 章 7.1.2），而 Q6_K 只需要一个 `int8_t` 数组，每个子块对应一个整数，完全没有打包这一步。解码时，`d · scales[j]` 直接就是该子块的有效尺度。


## 9.2 公式与反量化

### 9.2.1 \(y_i = d \cdot \mathrm{scales}[j] \cdot (q_i - 32)\)

Q6_K 的反量化公式是：

\[
y_i = d \cdot \mathrm{scales}[j] \cdot (q_i - 32)
\]

这里的 \(j = \lfloor i/16 \rfloor\) 是子块索引，\(q_i \in [0,63]\) 则是 6-bit 码。**减 32** 这一步，把无符号的码平移成了关于 0 对称的量：\(q_i - 32 \in [-32, 31]\)，恰好覆盖一个近似对称的有符号范围。

和 Q4_K 放在一起对比：

```
Q4_K:   y = d · s_j · q_i − d_min · m_j      （非对称：有最小值偏移）
Q6_K:   y = d · scales[j] · (q_i − 32)       （对称：无偏移，码减 32）
```

Q6_K 是用"码减 32"来实现对称化的，这条思路和 Q4_0 的 \(d(q-8)\) 如出一辙（第 4 章 4.2.2）：两者都是**把存储偏移变成解码端的一次整数减法**，不必多消耗任何一个字节。

### 9.2.2 反量化的精确位序：`ql` 低 4 位 + `qh` 高 2 位

6-bit 码的合成方式和 Q5_K 类似，只是更细一些。这里以 128 个值为一个处理单元：`ql` 每个字节里的两个 nibble，分别属于**相隔 64 个位置**的两个值；而 `qh` 每个字节里的 4 个 2-bit 组，则属于**相隔 32 个位置（也就是 stride-32）**的 4 个值。设当前处理单元的起点偏移为 \(j\)（\(j = 0\) 或 128）：

```
ql[l] 与 qh[l] 的位布局（以第 l 个字节为例）

  ql[l]        ┌──────────────┬──────────────┐
               │ 低 4 位       │ 高 4 位       │
               │ position j+l │ position j+l+64│
               └──────────────┴──────────────┘

  ql[l+32]     ┌──────────────┬──────────────┐
               │ position j+l+32│ position j+l+96│
               └──────────────┴──────────────┘

  qh[l]        ┌─────┬─────┬─────┬─────┐
               │bit0-1│bit2-3│bit4-5│bit6-7│
               │ j+l │j+l+32│j+l+64│j+l+96│
               └─────┴─────┴─────┴─────┘
```

换句话说，某一个位置的 6-bit 码，是由**两个平面共同拼出来的**：同一位置的低 4 位放在 `ql` 里，高 2 位放在 `qh` 里。比如位置 \(j+l\) 的码，等于 `ql[l]` 的低 4 位加上 `qh[l]` 的 bit0-1；而位置 \(j+l+96\) 的码，则等于 `ql[l+32]` 的高 4 位加上 `qh[l]` 的 bit6-7。

ggml 的 `dequantize_row_q6_K` 会依次拼出 4 个 6-bit 码（分别属于 4 个相邻的子块），然后把它们减去 32，再乘以各自对应的 `d·scales[j]`：

```c
for (int n = 0; n < QK_K; n += 128) {          // 两个 128 值半块
    for (int l = 0; l < 32; ++l) {
        int is = l/16;                          // 子块对索引：0 或 1
        const int8_t q1 = (int8_t)((ql[l+ 0] & 0xF)   | (((qh[l] >> 0) & 3) << 4)) - 32;
        const int8_t q2 = (int8_t)((ql[l+32] & 0xF)   | (((qh[l] >> 2) & 3) << 4)) - 32;
        const int8_t q3 = (int8_t)((ql[l+ 0] >> 4)    | (((qh[l] >> 4) & 3) << 4)) - 32;
        const int8_t q4 = (int8_t)((ql[l+32] >> 4)    | (((qh[l] >> 6) & 3) << 4)) - 32;
        y[l +  0] = d * sc[is + 0] * q1;
        y[l + 32] = d * sc[is + 2] * q2;
        y[l + 64] = d * sc[is + 4] * q3;
        y[l + 96] = d * sc[is + 6] * q4;
    }
    y += 128; ql += 64; qh += 32; sc += 8;
}
```

读这段代码时，要特别留意 `qh[l] >> 0 / >> 2 / >> 4 / >> 6` 这几处：一个 `qh` 字节里的 4 个 2-bit 组，依次属于 stride-32 的 4 个位置（\(j+l, j+l+32, j+l+64, j+l+96\)）；而对应位置的低 4 位，则分别由 `ql[l]` 与 `ql[l+32]` 的低/高 nibble 补齐。这和 Q5_K"一个字节里放多个位置的位"是同一套思路，区别只在于每组从 1 位变成了 2 位，而且并进了 `ql` 的 nibble 主体。

**C++（即上面的循环，整理为函数）：**

```cpp
// 解码一个 128 值半块（8 个 16 值子块）
// ql: 64 字节低 4 位，qh: 32 字节高 2 位，sc: 8 个 int8 尺度
static void unpack_q6_k_half(const uint8_t * ql, const uint8_t * qh,
                             const int8_t * sc, float d, float * y) {
    for (int l = 0; l < 32; ++l) {
        const int is = l/16;
        const int8_t q1 = (int8_t)((ql[l+ 0] & 0x0F) | (((qh[l] >> 0) & 3) << 4)) - 32;
        const int8_t q2 = (int8_t)((ql[l+32] & 0x0F) | (((qh[l] >> 2) & 3) << 4)) - 32;
        const int8_t q3 = (int8_t)((ql[l+ 0] >> 4)   | (((qh[l] >> 4) & 3) << 4)) - 32;
        const int8_t q4 = (int8_t)((ql[l+32] >> 4)   | (((qh[l] >> 6) & 3) << 4)) - 32;
        y[l +  0] = d * sc[is + 0] * q1;
        y[l + 32] = d * sc[is + 2] * q2;
        y[l + 64] = d * sc[is + 4] * q3;
        y[l + 96] = d * sc[is + 6] * q4;
    }
}
```

**Python：**

```python
def unpack_q6_k_half(ql: bytes, qh: bytes, scales: list[int], d: float) -> list[float]:
    """解码一个 128 值半块（8 个 16 值子块）。

    ql: 64 字节低 4 位平面；qh: 32 字节高 2 位平面；
    scales: 8 个 int8 子块尺度；d: 超级块尺度。
    """
    y = [0.0] * 128
    for l in range(32):
        is_ = l // 16
        q1 = ((ql[l]     & 0x0F) | ((qh[l] >> 0 & 3) << 4)) - 32
        q2 = ((ql[l + 32] & 0x0F) | ((qh[l] >> 2 & 3) << 4)) - 32
        q3 = ((ql[l]     >> 4)   | ((qh[l] >> 4 & 3) << 4)) - 32
        q4 = ((ql[l + 32] >> 4)  | ((qh[l] >> 6 & 3) << 4)) - 32
        y[l]      = d * scales[is_ + 0] * q1
        y[l + 32] = d * scales[is_ + 2] * q2
        y[l + 64] = d * scales[is_ + 4] * q3
        y[l + 96] = d * scales[is_ + 6] * q4
    return y
```

三种实现逐行都能对应上。在 Python 里，`sbyte` 的溢出问题，靠"减 32 之后已经落在 [-32,31]"这一点自然就处理掉了；C# 则用显式的 `sbyte` 转换，来保持和 C++ 的 `int8_t` 一致。

**手工验证**：设 `d = 1.0`，8 个尺度全都取 1，`ql[l] = 0x00`、`qh[l] = 0xE4`。`0xE4 = 1110 0100`，按组逐段读出来就是：bit0-1 = `00`(0)、bit2-3 = `01`(1)、bit4-5 = `10`(2)、bit6-7 = `11`(3)。再按照修正后的位序（stride-32）来拼：
- `q1`（位置 `l`）：`ql[l]` 的低 4 位是 0，加上 `(qh[l]>>0)&3 = 0` → 得到码 `0 | (0<<4) = 0` → 于是 `q1 = 0-32 = -32`；
- `q2`（位置 `l+32`）：`ql[l+32]` 的低 4 位是 0，加上 `(qh[l]>>2)&3 = 1` → 得到码 16 → 于是 `q2 = -16`；
- `q3`（位置 `l+64`）：`ql[l]` 的高 4 位是 0，加上 `(qh[l]>>4)&3 = 2` → 得到码 `0 | (2<<4) = 32` → 于是 `q3 = 32-32 = 0`；
- `q4`（位置 `l+96`）：`ql[l+32]` 的高 4 位是 0，加上 `(qh[l]>>6)&3 = 3` → 得到码 `0 | (3<<4) = 48` → 于是 `q4 = 48-32 = 16`。

```python
scales = [1] * 8
d = 1.0
ql = bytes([0x00] * 64)
qh = bytes([0xE4] * 32)
y = unpack_q6_k_half(ql, qh, scales, d)
assert y[0]    == 1 * 1 * (-32)
assert y[32]   == 1 * 1 * (-16)
assert y[64]   == 1 * 1 * (  0)
assert y[96]   == 1 * 1 * ( 16)
print("手工验证通过：", y[0], y[32], y[64], y[96])
```

### 9.2.3 量化端：尺度是怎么选出来的

量化端会先为每个子块算出一个浮点尺度，然后拿整个超级块的**最大绝对值尺度**来做归一化：

```
量化一个超级块（参考实现简写）

  每个 16 值子块：
      scale = make_qx_quants(16, 32, 子块, 码, ...)   ← 子块尺度 + 码
  找全部 16 个子块中 |scale| 最大的：max_scale

  iscale = -128 / max_scale
  d      = 1 / iscale                     ← 超级块尺度（fp16）
  scales[j] = nearest_int(iscale * 子块scale[j])   ← 每个子块存 int8
  码 q = nearest_int(x / (d · scales[j])) + 32     ← 再转成 6-bit
```

这里的关键在 `iscale = -128 / max_scale`：它把最大的那个子块尺度映射到 -128（也就是 int8 的最小值），其余子块再按比例缩进 int8 的范围里。到了解码端，`d · scales[j]` 就把每个子块的有效尺度还原了出来，**不需要任何额外的除法常数**——因为归一化在量化端就已经做完了。这其实正是第 6 章 6.2.2 提过的"6-bit 参数除以 63 还是 64"这个问题，在 Q6_K 身上的解答：Q6_K 的尺度是 int8，归一化方式明确又统一，根本不存在 63 还是 64 的歧义。


## 9.3 实验与质量

### 9.3.1 Q6_K 的 PPL 与 KL

Q6_K 相对 F16 的 PPL 劣化，**约 +0.2%**（这只是一个量级参考，具体数值会随模型和评测集变化）。正是这个数字，让它成了 k-quant 家族里"质量几乎无损"的代表：在很多任务上，Q6_K 的输出和 F16 几乎区分不出来。

```
各档位质量/体积一览（示意，量级参考）

  bpw     4.5       5.5       6.5
  ────────┬─────────┬─────────┬──────────►
  PPL劣化  Q4_K     Q5_K     Q6_K
          ≈+0.8%   ≈+0.4%   ≈+0.2%
  体积     小       中        大
  适用     日常部署  质量敏感  高保真/输出层
```

用 `llama-perplexity` 跟 F16 基准模型对比时，Q6_K 的 KL 散度也远远低于 Q4_K。第 2 章说过，KL 散度对 logits 的形状更敏感；而 Q6_K 恰恰经常用在 logits 的最终源头，也就是输出层上，所以它的 KL 表现尤其值得关注——这正是 9.3.2 要讲的内容。

### 9.3.2 在混合精度配置中的角色

在一个 `Q4_K_M` 文件内部，Q6_K 张量通常只占一小部分——典型情况就是 `output.weight`（有时还包括 `token_embd.weight`），总共也就一两个张量。可它们对整体输出质量的影响，却是**超比例**的：

```
Q4_K_M 文件里的 Q6_K 角色（示意）

  ┌──────────────────────────────────────────┐
  │  绝大多数张量：Q4_K（约 98% 的体积）        │
  │  ┌────────────────────────────────────┐  │
  │  │ attn_q/attn_k/attn_v/ffn_* ...    │  │
  │  └────────────────────────────────────┘  │
  ├──────────────────────────────────────────┤
  │  极少数张量：Q6_K（输出层）               │
  │  ┌────────────────────────────────────┐  │
  │  │ output.weight → 直接决定 logits     │  │
  │  └────────────────────────────────────┘  │
  └──────────────────────────────────────────┘
```

为什么输出层值得多花这份精度？因为**输出层就是 logits 的直接来源**：最终的概率分布 \(P(\text{token})\)，是由 \(W_{\text{out}} \cdot h\) 经过 softmax 得到的。这里的量化误差，不会像 FFN 内部那样被后续的层"稀释"掉，而是会直接变成概率分布上的扰动——一个权重差上 0.05，就可能改变某个 token 的排序。所以，对输出层使用更高的位宽，本质上就是"把误差预算花在最关键的地方"。

这也正好呼应了第 3 章 3.2.3 那张混合类型表：`output.weight` 用 Q6_K，`attn_*`/`ffn_*` 用 Q4_K，而归一化层用 F32。第 14 章会从敏感度的角度，系统地分析为什么要这样分配。


## 本章小结与通往 Q2_K/Q3_K 的桥梁

这一章的内容，同样可以压缩成三个事实。

**第一，Q6_K 采用"16 个子块 × 16 值 + 8-bit 有符号尺度 + 无偏移"的结构。** 它把 Q4_K 那套"8×32 + 6-bit 尺度 + 最小值偏移"的骨架改得更简单，也更精细：每个子块只有一个 `int8_t` 尺度，没有 `dmin`，也没有复杂的交错打包。整个块一共 210 字节，有效位宽 6.5625 bpw。

**第二，反量化公式是 \(y = d \cdot \mathrm{scales}[j] \cdot (q - 32)\)。** 6-bit 码被拆成低 4 位（`ql`）和高 2 位（`qh`）两个平面，`qh[l]` 里的 4 个 2-bit 组，依次属于 4 个相邻的子块。归一化在量化端就已经完成，解码端直接乘 int8 尺度即可，没有 63/64 的歧义。

**第三，Q6_K 是输出嵌入层的默认选择。** 它的 PPL 劣化大约是 +0.2%，在 `Q4_K_M`/`Q5_K_M` 文件里通常只占一两个张量，但因为输出层直接决定了 logits，它对整体质量的贡献是超比例地大。

```
k-quant 家族的位宽梯度

  Q2_K   Q3_K   Q4_K   Q5_K   Q6_K
  ├──────┼──────┼──────┼──────┤
  2.6   3.4    4.5    5.5   6.6   bpw
  │      │      │      │      │
  ←─ 极限压缩 ─→     ←─ 高保真 ─→
```

下一章，我们把目光转向梯度的另一端：Q2_K 和 Q3_K。它们把位宽压到了 3 bpw 以下，用到的打包技巧也更加密集——Q2_K 甚至把尺度系数和最小值系数各自塞进了同一个字节的一半里。那是"再压一点"的故事，也是 k-quant 家族失效边界所在的地方。
